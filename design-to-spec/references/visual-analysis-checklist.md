# 视觉分析检查清单

在步骤 1 中线性浏览此内容。**写下你观察到的内容** —— 此步骤的产出是元素的结构化列表，不是散文段落。明确的"无"是有效且有用的（例如，"未显示错误状态"、"未显示加载骨架"）。

目标是证据收集，不是解释。将解释留到步骤 3 及之后。

## A. 容器

- 整体形状和圆角
- 背景色（主背景，不是内容）
- 阴影/elevation
- 内边距（近似值 —— "紧凑"、"宽松"或百分比）
- 卡片是放在中性页面上还是有色背景上（背景可以暗示暗色模式或主题化）

## B. 标题/头部区域

- 标题文本（逐字）
- 副标题/眉标文本（逐字）
- 标题行内的任何徽章或标签
- 右侧 affordance（chevron、"更多"链接、图标按钮）

## C. 内容正文 — 结构通道

从头到脚、从左到右浏览内容。对于每个区域：

- 近似边界框位置（左上/中心/右下）
- 其相对于兄弟元素的作用（是列表行、媒体槽、CTA 行？）
- 它是否与邻居视觉分组（共享背景、分隔符、间距间隙）

## D. 内容正文 — 元素通道

对于每个不同元素，捕获：

- **文本内容，逐字**，包括：
    - 截断标记（`…`、`...`）
    - 标点符号、空白、大小写
    - 数值及其单位（`+5.14%`、`¥1,234`）
- **图标/插图存在**：描绘了什么、近似尺寸
- **图片存在**：照片、图表、头像 —— 注意模式（方形、圆形、图表）
- **复合图片资产辨识**：看到「渐变背景 + 堆叠文字 + 规则边界」的视觉单元（徽章、角标、标志性图标、活动入口图）时，**默认假设它是单一的设计交付图片（PNG/WebP）**，而非代码绘制的 rect + text 组合。在数据契约里用 URL 字段（例如 `badgeIconUrl` / `iconUrl`）承载，并让 Scenario 断言 DOM 为 `<image>`。典型信号：垂直/斜向渐变、像章状外形、紧凑堆叠的"热"/"点""NEW""VIP"等短文字、明显的品牌化视觉风格。错把它拆成 primitives 会引入两类回归——跨端字体渲染漂移，以及活动换图必须发版（而不是设计换 URL 就生效）。只有当设计明确标注"代码绘制"或"engineering ticker"时才按 primitives 拆。
- **颜色强调**：主品牌色、次要文本灰色、危险红、成功绿
- **字重/尺寸强调**：粗体数字、显示尺寸标题
- **交互 affordance**：按钮形状、chevron、下划线、标签边框

## E. 注释和边距笔记

Mockup 通常在画板外带有设计师笔记。这些是**规定性的**，不能遗漏。示例：

- "一行2，固定宽度" —— 规定布局（每行两个，固定宽度）
- "max 20 chars" —— 规定截断
- "Tap to expand" —— 规定交互
- 带文本标签指向元素的箭头
- 图片旁边的手写或打字评论

逐字捕获每个注释，并将其绑定到它修改的元素。

## F. 隐含交互提示

这些并不总是有明确的注释，但带有强烈的惯例：

- 行右侧的 `>` chevron → 行导航到详情视图
- 轮廓药丸按钮 → 可点击的 CTA
- 正文中的下划线文本 → 可点击链接
- 头像/图表缩略图 → 点击打开项目
- 火/火焰/hot-tag → 信号强调，通常可点击作为过滤器
- 整个卡片被微妙的外阴影包围 → 卡片本身可能作为 feed 项目可点击

列出你看到的每一个，但标记为 `inferred`（不是 `identified`），除非注释另有说明。

## G. 未显示的状态

明确注意以下内容的缺失：

- 加载/骨架状态
- 空状态（无数据）
- 错误状态
- CTA 的禁用状态
- 选中/按下状态

缺失是信号 —— 这意味着实现者需要自己设计这些状态，规格应该将其表面化为开放问题。

## H. 负空间和尺寸关系

- 卡片在视口上是边缘到边缘，还是有 inset？
- 行之间的垂直间隙是相等还是不相等？（不相等通常表示区域。）
- 是否仅通过尺寸建立视觉层次（例如，价格是标签的 2 倍）？

## I. 平台/密度信号

- Mockup 是否显示状态栏、刘海、主屏幕指示器？（暗示目标平台。）
- 类型刻度是紧凑的（小程序/密集产品列表）还是宽敞的（英雄着陆页）？
- 颜色是饱和且品牌向前的（消费级）还是柔和的（企业级）？

## J. 你无法从图片中判断的内容

以无法回答的问题的明确列表结束检查清单。典型候选者：

- 每个交互元素导航到哪里？
- 长按会发生什么？
- 数据缺失时的行为是什么？
- 微型图表如何处理无数据？
- 布局是响应式的（宽度自适应）还是锁定在单一宽度？
- 无障碍阅读顺序是什么？仅图标控件是否有无障碍标签？

这里的每个项目成为 `notes.md` 的「开放问题」小节条目。
