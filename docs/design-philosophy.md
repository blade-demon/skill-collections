# 设计哲学

## 核心理念

### 确定性优于智能性

系统优先追求**可预测的输出**而非"聪明"的行为。每个处理阶段的输出必须是确定性的，避免随机性干扰调试和测试。

**体现**：

- 零大模型依赖的规则引擎设计
- 分阶段门禁验证机制
- 字节级等价的回归测试

### 分离关注点

每个模块只负责单一职责，通过明确的接口协作。

**体现**：

- Provider抽象：隔离不同设计源的复杂度
- Design IR：统一的中间表示避免N×M的适配问题
- Service层：业务逻辑与基础设施分离

### 增量改进

支持渐进式增强，每个阶段都可以独立优化和验证。

**体现**：

- Stage 0-6的阶段式管线设计
- IR保真度审计机制（A1-A6缺陷分批次修复）
- 门禁点验证：每阶段输出都有质量检查

## 设计模式借鉴

### 编译器设计模式

类似于传统编译器的前端→中端→后端架构：

```
设计源 → [Parser] → AST → [Optimizer] → IR → [Codegen] → 目标代码
Sketch     Extract     Raw     Normalize    IR      Contract    React/Vue
```

### 管道和过滤器模式

每个处理阶段都是独立的过滤器，通过标准化数据格式连接：

**优势**：

- 可测试性：每个过滤器可以独立测试
- 可替换性：替换某个阶段不影响其他阶段
- 并行性：不同skill可以并行开发

### 适配器模式

Provider接口统一了不同设计源的访问方式：

```typescript
interface DesignProvider {
  extract(input: unknown): Promise<RawDesign>;
  normalize(raw: RawDesign): Promise<DesignIR>;
}
```

## 质量理念

### 契约式编程

通过明确的Schema定义输入输出契约：

- JSON Schema验证确保数据结构正确性
- TypeScript类型确保编译时安全性
- 测试用例确保运行时行为正确性

### 门禁驱动开发

每个开发阶段都有明确的质量门禁：

1. **代码门禁**：lint + typecheck + format
2. **功能门禁**：单元测试 + 集成测试
3. **回归门禁**：golden sample验证
4. **发布门禁**：完整CI流水线

### 防御式设计

假设输入不可信，假设环境不稳定：

- 输入验证：所有外部输入都经过Schema验证
- 错误处理：提供有意义的错误消息
- 优雅降级：部分功能失败不影响整体流程

## 开发体验理念

### 本地优先

所有操作都可以在本地完成，不依赖外部服务：

- 离线可用：核心功能不需要网络
- 快速反馈：本地测试覆盖关键路径
- 可重现：确定性处理确保结果一致

### 文档驱动

文档与代码同步维护，文档即规格：

- README作为入口点
- 内联注释解释WHY而非WHAT
- 架构决策记录（ADR）追踪重要设计

### 工具链统一

标准化开发工具减少认知负担：

- 统一的代码规范（ESLint + Prettier）
- 统一的测试框架（Node.js test runner）
- 统一的构建工具（TypeScript + npm scripts）

## 反模式规避

### 避免大泥球

通过明确的模块边界和依赖管理防止代码腐化。

### 避免过早优化

先确保正确性和可维护性，再考虑性能优化。

### 避免供应商锁定

使用开放标准和可替换的依赖，避免与特定工具绑定。

### 避免配置地狱

提供合理的默认值，配置项有清晰的文档和验证。
