# 中断恢复与取材策略

> 续跑、或不确定「这一阶段该看哪些文件」时读本文。两件事：① 怎么从中断处接着跑；② 怎么做到「只看一组相关文件」而不是扫全仓。

## 一、中断恢复

这个 skill 的每个阶段都把结论落盘到 `docs/.analysis/`，所以**关掉会话也能接着跑**。新会话被调用时：

1. **先探测进度**，不要默认从 P1 开始。用 Glob 看 `docs/.analysis/` 下**带序号的阶段产物**（只看 `0N-` 文件），取**已存在的最高序号**判断：

   | 已存在的最高序号阶段产物        | 下一步起点             |
   | ------------------------------- | ---------------------- |
   | （目录为空/不存在）             | P1                     |
   | `01-discovery-report.md`        | P2                     |
   | `02-frontend-index.md`          | P3                     |
   | `03-backend-index.md`           | P4                     |
   | `04-api-map-draft.md`           | P5                     |
   | `05-business-flows-draft.md`    | P6                     |
   | `06-data-model-draft.md`        | P7                     |
   | `docs/` 下 8 份最终文档已存在   | P8                     |
   | `08-validation-report-draft.md` | P8 进行中（续跑/重跑） |

   > ⚠️ **探测时忽略不带序号的常驻文件**（`evidence-ledger.md`，以及可选的 `git-insights.md`、`endpoints-seed.json`）：它们不代表阶段进度。不要用「按文件名排序取最后一个」的方式探测——这些文件会排在所有 `0N-` 文件之后，把你误导到错误阶段。只按上表里**带序号的产物**的最高序号判断。

2. **读起点阶段需要的上一阶段产物**作为输入（如 P4 读 `02`+`03`），不要重新扫源码重建它们。

3. 用户也可显式指定：「从 Phase 5 继续」「重跑 P2」。显式指定优先于探测。

4. 重跑某阶段时，**覆盖**对应 `.analysis` 文件，并清理它在证据账本里登记的过期条目（按 `E-编号` 的类型/路径定位）。

> 恢复提示话术（粘给用户）：
> `docs/.analysis/ 已有 01~03，我从 Phase 4（API 映射）继续；如需重跑某阶段请说「重跑 PN」。`

## 二、「只看一组相关文件」取材策略

弱模型一次吞整个仓库必然幻觉。每阶段只取**该阶段真正需要的最小文件集**：

| 阶段        | 只看                                                       | 明确不看                                 |
| ----------- | ---------------------------------------------------------- | ---------------------------------------- |
| P1 探索     | README、构建配置、入口文件、各层**目录**（先列表不深读）   | 任何业务方法体细节                       |
| P2 前端索引 | 前端：路由文件、`api/` 封装、`pages/`、`store/`、拦截器    | 整个后端                                 |
| P3 后端索引 | 后端：Controller/Service/Repository/Model **声明**、Config | 整个前端、方法内部实现细节               |
| P4 API 映射 | 只读 `02`、`03` 两份产物                                   | 源码（除非要核对某条拼接，再点开单文件） |
| P5 业务链路 | 选中的 3~6 条链路**沿途**的文件，逐链路打开                | 与所选链路无关的模块                     |
| P6 数据模型 | 核心链路/核心接口涉及的模型类 + 其 Mapper XML              | 边缘 POJO、未被引用的模型                |
| P7 文档生成 | 只读 `.analysis` 产物 + 证据账本，装配正文与 Mermaid       | 源码（P7 不重新读代码）                  |
| P8 校验     | 最终文档 + 脚本结果 + 点查被质疑的具体路径/符号/连线证据   | 全量重读、执行目标项目构建/测试命令      |

### 取材手法

- 用 Glob 先列清单（环境有 ripgrep 时 `rg --files` 亦可），再决定打开哪几个，不要一次性读目录下所有文件全文。
- 大文件只读相关段：先 Grep 关键符号定位行号，再按行号窗口读。
- 一个阶段读过的文件，落盘后即可从工作记忆释放——下一阶段需要时通过 `.analysis` 产物间接引用，而不是重读源码。

### context 不足时

若中途感到 context 紧张：**立即把当前阶段已得到的结论落盘**，输出一行「已落盘到 `docs/.analysis/0N-...`，请开新会话发送『从 Phase N 继续』」，然后停止。已落盘的内容不会丢，恢复协议会接上。
