# Validation Record 格式

`docs/.analysis/08-validation-report-draft.md` 与 `docs/validation-report.md` 里每个校验项的记录格式。

## 单条校验记录

```markdown
## V-<编号>：<校验项名称>

- 校验对象：<哪份文档的哪条结论 / 哪条命令>
- 校验方法：<Glob / Grep / 运行命令 / 交叉比对>
- 期望：<应当成立的事实>
- 实际：<核对结果，附证据 path:line 或命令输出摘要>
- 判定：通过 / 不通过
- 处理：<不通过时按失败处理规则做了什么——修正/降级/移待确认>
- 关联 Evidence：<E-xxx，如有>
```

## 字段规则

| 字段     | 规则                                                         |
| -------- | ------------------------------------------------------------ |
| 编号     | `V-001` 起递增。                                             |
| 校验方法 | 优先可机械执行的方法（Glob/Grep/运行命令），避免「凭印象」。 |
| 实际     | 必须附可复核的证据：路径、行号或命令输出摘要。               |
| 判定     | 只有「通过 / 不通过」，不要「大概通过」。                    |
| 处理     | 不通过必须落实到一条具体动作，并回写对应最终文档。           |

## 命令可执行性记录（对应 checklist 第 10 项）

```markdown
| 命令            | 是否成功 | 退出码 | 输出摘要             | 是否影响文档            |
| --------------- | -------- | ------ | -------------------- | ----------------------- |
| `npm run build` | 是/否    | 0/非0  | <关键输出或报错首行> | 否 / 是——影响 <文档:节> |
```

> 命令失败 ≠ 文档错误。如实记录失败本身即可，并单独判断它是否影响文档结论的准确性。

## 严重度分级（用于「发现的问题」表）

| severity | 含义                               | 处理时限建议           |
| -------- | ---------------------------------- | ---------------------- |
| 高       | 把不存在的路径/符号/链路写成了事实 | 必须在定稿前修正       |
| 中       | 推测被写成事实，或文档间措辞矛盾   | 定稿前降级或对齐       |
| 低       | 表述不清、缺交叉引用               | 可记入待确认，后续完善 |
