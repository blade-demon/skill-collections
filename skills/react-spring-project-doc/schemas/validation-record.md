# Validation Record 格式

`docs/.analysis/08-validation-report-draft.md` 与 `docs/validation-report.md` 里每个校验项的记录格式。

## 单条校验记录

```markdown
## V-<编号>：<校验项名称>

- 校验对象：<哪份文档的哪条结论 / 哪张 Mermaid 的节点或连线>
- 校验方法：<validate-docs.js / Glob / Grep / 对照 P4/P5 / 交叉比对>
- 期望：<应当成立的事实>
- 实际：<核对结果，附证据 path:line、Evidence ID 或脚本输出摘要>
- 判定：通过 / 不通过
- 处理：<不通过时按失败处理规则做了什么——修正/降级/移待确认>
- 关联 Evidence：<E-xxx，如有>
```

## 字段规则

| 字段     | 规则                                                          |
| -------- | ------------------------------------------------------------- |
| 编号     | `V-001` 起递增。                                              |
| 校验方法 | 优先脚本、Glob/Grep、P4/P5 对照等可复核方法，避免「凭印象」。 |
| 实际     | 必须附可复核的证据：路径、行号、Evidence ID 或脚本输出摘要。  |
| 判定     | 只有「通过 / 不通过」，不要「大概通过」。                     |
| 处理     | 不通过必须落实到一条具体动作，并回写对应最终文档。            |

## Mermaid 校验记录

```markdown
| 文档              | 图         | Evidence          | 节点/连线核对 | 结果        |
| ----------------- | ---------- | ----------------- | ------------- | ----------- |
| `architecture.md` | 运行时全景 | E-001/E-003/E-013 | 对照 P2/P3/P4 | 通过/不通过 |
```

> P8 暂不执行目标项目的构建、测试、lint、typecheck 命令；校验记录只描述静态文档、图和代码证据。

## 严重度分级（用于「发现的问题」表）

| severity | 含义                               | 处理时限建议           |
| -------- | ---------------------------------- | ---------------------- |
| 高       | 把不存在的路径/符号/链路写成了事实 | 必须在定稿前修正       |
| 中       | 推测被写成事实，或文档间措辞矛盾   | 定稿前降级或对齐       |
| 低       | 表述不清、缺交叉引用               | 可记入待确认，后续完善 |
