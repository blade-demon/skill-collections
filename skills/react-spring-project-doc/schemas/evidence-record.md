# Evidence Record 格式

证据账本 `docs/.analysis/evidence-ledger.md` 里每条记录的字段定义。P2~P6 每得到一个会进入最终文档的结论，追加一条。

## 字段格式

```markdown
## Evidence: E-<编号>

- 结论：<一句话陈述，可被代码验证>
- 类型：前端模块 / 后端模块 / API 映射 / 业务链路 / 数据模型 / 配置 / 权限 / 异常处理
- 文件路径：<相对项目根的真实路径>
- 符号：<类 / 方法 / 函数 / 组件名；无具体符号时写「目录级」>
- 代码位置：<path:line 或 path 范围>
- 证据说明：<为什么这条结论成立——指向哪段调用/注解/配置/测试/类型>
- 置信度：高 / 中 / 低
- 状态：确定 / 推测 / 待确认
- 是否允许进入最终文档：是 / 否
```

## 字段规则

| 字段       | 规则                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------- |
| 编号       | 全局唯一、单调递增：`E-001`、`E-002`…；跨阶段不重置。                                    |
| 结论       | 必须是可被代码验证的陈述句，不写主观评价。                                               |
| 类型       | 取枚举值之一，便于 P7 按类型聚合到对应文档。                                             |
| 文件路径   | 必须真实存在（P8 会 Glob 核对）；不存在则本条不能登记为「确定」。                        |
| 符号       | 必须能被 Grep 到（P8 会核对）；找不到则降级。                                            |
| 置信度     | 按下表判定。                                                                             |
| 状态       | 与置信度联动：高→可「确定」；中→「推测」；低→「待确认」。                                |
| 是否进文档 | 「确定」「推测」可进（推测需在文档里标注）；「待确认」不进正文，进文档的「待确认项」节。 |

## 置信度判定

| 置信度 | 判据                                                 | 允许的状态 |
| ------ | ---------------------------------------------------- | ---------- |
| 高     | 有明确的代码调用、注解、配置、测试或类型定义直接支持 | 确定       |
| 中     | 仅靠命名、目录结构、调用关系合理推断                 | 推测       |
| 低     | 代码证据不足，无法验证                               | 待确认     |

> **联动铁律**：置信度「中」的结论进文档时必须带「（推测）」字样；置信度「低」的结论**禁止**进任何文档正文，只能进「待确认项」。P8 会反查越级。
