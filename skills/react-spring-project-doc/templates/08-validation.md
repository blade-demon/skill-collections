# Phase 8 — Evidence-Based Validation 模板

> 草稿先落 `docs/.analysis/08-validation-report-draft.md`，定稿写 `docs/validation-report.md`。
> 对 P7 生成的最终文档做强校验。逐项核对——**能用工具核对的就核对**（Glob 查路径、Grep 查符号、跑构建命令），不要凭印象判过。
> 每个校验项按 `schemas/validation-record.md` 记录。发现问题按「失败处理规则」修正文档或降级结论，并回写。

## 校验 checklist

| #   | 校验项                              | 方法                           | 结果              | 处理                                     |
| --- | ----------------------------------- | ------------------------------ | ----------------- | ---------------------------------------- |
| 1   | 文档引用的文件路径真实存在          | Glob/ls 逐条核对               | <通过/N 处失效>   | <修正或移待确认>                         |
| 2   | 类名/方法名/函数名/组件名真实存在   | Grep 核对                      | <通过/N 处失效>   | <删确定结论或移待确认>                   |
| 3   | 前端 API 能映射到后端 Controller    | 对照 api-map                   | <通过/N 处未匹配> | <标未匹配，不写成完整链路>               |
| 4   | 后端 Controller 能反查到前端调用    | 对照 api-map                   | <通过/N 处未匹配> | <标注，不臆测>                           |
| 5   | 核心业务链路闭环                    | 对照 business-flows            | <闭环/部分/断点>  | <标部分完整或待确认>                     |
| 6   | 文档结论有证据支撑                  | 抽查对照证据账本               | <通过/N 处无证据> | <降级为推测或待确认>                     |
| 7   | 文档之间无矛盾                      | 交叉比对                       | <一致/N 处矛盾>   | <修正后重记证据>                         |
| 8   | 未把废弃代码当核心业务              | 检查 deprecated/未引用/示例    | <通过/N 处存疑>   | <标待确认或移除>                         |
| 9   | 低置信度未被误写成事实              | 抽查证据账本置信度 vs 文档措辞 | <通过/N 处越级>   | <降级措辞>                               |
| 10  | 构建/测试/lint/typecheck 命令可执行 | 实际运行 `01` 记录的命令       | <逐条 通过/失败>  | <记录失败命令、原因、是否影响文档准确性> |

## 失败处理规则

1. **文件路径不存在** → 修正文档，或移入「待确认项」。
2. **符号不存在** → 删除确定结论，或移入「待确认项」。
3. **API 映射失败** → 标注「未匹配」，不得写成完整链路。
4. **业务链路不闭环** → 标注「部分完整」或「待确认」。
5. **结论无证据** → 降级为「推测」或「待确认」。
6. **文档矛盾** → 修正后在证据账本重新记录。
7. **构建/测试失败** → 记录失败命令、失败原因、是否影响文档准确性（命令失败不一定等于文档错，但要如实记录）。
